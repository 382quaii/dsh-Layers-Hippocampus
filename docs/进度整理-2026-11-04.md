## 0. 一句话结论

raw 的"准确率"分两层：写入无损 100%；检索精确命中但信噪比低。当前真正的短板不在 raw，而在
**细粒度标签 / 相关边 / 跨会话自动衔接**；其中"自动开新会话"受 Host API 限制，需要走
"工作区交接文件"或 `session-switch` 式 HTTP 握手，不能靠记忆插件单方面完成。

## 1. raw 层（L1 黑匣子）

| 维度 | 结论 | 状态 |
| --- | --- | --- |
| 写入保真 | 不摘要、不打标、不改写，字节级忠实；高熵密文拦截（`MEM_E_ENCRYPTED_RAW_REJECTED`） | 文档所述；仓库有 `rawStore.js` 纯净四字段 + raw 门控，未实现密文拦截 |
| `deep_raw` 命中 | 按行流式扫描 JSONL，时间窗/Hash 精确匹配 100% | 已实现（`readLinesReverse` 流式、绝对行号、结果硬上限） |
| 信噪比 | raw 什么都存，无约束时召回质量低；应先用 L1.5 标签 → L2 经验 | 架构已按此分层 |
| 语义检索 | 当前只有关键词/时间窗，无分词模糊打分 | **可选增强未实现**：关键词分词模糊匹配 + 命中词数排序 |

## 2. 标签体系：泛化陷阱 → 多维细粒度

**问题**：讨论"建设记忆插件的 LLM 功能"时只打出 `domain:memory-plugin`，未提取 `feature:llm`/`task:llm-distill`。

**已定方向**
1. 多维命名空间：`domain:*` / `task:*` / `feature:*` / `error:*`；
2. Pre-ingest 规则升级：不只抓名词，增加"动词 + 对象"（开发/建设/实现 + LLM → `task:llm-feature`）；
3. 若接 LLM 打标：Prompt 强制 1–3 个细粒度标签，禁止只返回宏观大类；
4. L1.5 层级：**后来修正**——不按单次输入强建父子，改由历史共现决定弱关联。

**仓库现状**
- `src/tagging.js` 已有确定性锚点：`error:typeerror`、`error:econnrefused`、`lang:python`、`http:500`、`file:index.js`、`task:*`；默认只取 2 个标签。
- 没有 `feature:*` 维度，也没有 LLM 打标（LLM 目前只用于 Dream 蒸馏）。
- 因此"`feature:llm` 细粒度打标"**未实现**。

## 3. L1.5 标签网络：放弃强父子，改共现统计

**否决的方案**：单次输入同时出现 A/B 就建父子（"24 号混凝土拌意大利面"会生成荒谬图谱）。

**已定方案**
1. 入库**平铺**，禁止单次强关联；跨域违和组合加 `anomaly:cross-domain`；
2. `maintain()` 离线统计标签共现：`Map` 键值对（`"tagA->tagB": count`），**零依赖、无向量、无余弦相似度**；
3. 仅当 `count > 硬阈值`（如 5/10）才建**平级"相关边"（Related To）**，**不建 Is-A 父子**；
4. 边必须可解释：记录 `source_event_ids`；30 天未增强的弱边在 `maintain()` 中 GC。

**仓库现状**
- `tagTreeRebuild.js` 按 `tag/路径` 建 L1.5 **层级树**（root/mid/leaf），没有"相关边"、没有 `anomaly`、没有共现频次表。
- `graph.js` 已有**事件级**共现边（同一事件内标签对 + 每节点 Top-N + 全局权重排序），但那是"共现图"，不是文档要求的"历史统计 + 阈值 + 可解释 + GC 的 L1.5 相关边"。
- 结论：**共现统计 + 相关边 + anomaly 标签均未实现**。

## 4. 自动开启新会话（当前最大阻塞）

**文档结论**
- `Session` 是仅追加事件日志，不能"命令"它执行操作；
- `ctx.agents.create({sessionId, agentOptions, setup})` / `resume(...)` 可程序化创建/恢复 Agent，但**不会让 UI 切换**；
- `workspaceRegistry.create / attachSession / archiveSession / unarchiveSession` 管挂载与归档，`attachSession` 后还需发 `api-session/added` 侧边栏才出现；
- `ctx.sessions.fork` 仅 live 会话；Web Remote `session.fork` 支持冷会话；
- agent tool 面**没有** `session_create`/`session_fork`/`new_session`；
- 现成参考：`dsh-session-switch` 用 4 条 HTTP 路由 + `pending.json` 握手（Host 建会话/写 pending，Client 读 pending → 切换 → ack）。

**方案演进（均未实现）**
1. 剪贴板交接（复制摘要 + 提示新建对话）——被否，UX 一般；
2. 临时交接文件 + 24h 后台清理——被否，用户要找文件；
3. **工作区交接文件（最终方向）**：
   - 在活跃 Workspace `.dsh/handoff/` 生成 `HANDOFF-<ts>-<id>.md`；
   - 内容：交接摘要、`[Active Task]`、工作模式；头部写 `SYSTEM_INSTRUCTION: 读取后删除此文件`；
   - UI 只给一条可复制 Prompt：`请先读取 <绝对路径>，读取后删除，然后继续工作`；
   - AI 用工作区权限自行读取 + 删除；插件在 `maintain()` 兜底清理 24h 旧文件。

**本会话对 Host 服务的实测**（与文档存在差异，需实测确认）
- `sessions` 服务：`create()` 明确"published outside lifecycle persists nothing"，只创建内存 session；
- `agents` 服务 catalog 可见部分只有 `currentInitiator/requireInitiator/withInitiator/withoutInitiator`，**未确认** `create/resume` 是否真的挂在该服务上（catalog 中段被截断）；
- 未发现公开的"激活/切换 UI 会话"服务；
- 结论：**自动开新会话需要 Host 侧能力或 `session-switch` 式 HTTP+Client 握手；工作区交接文件是当前可行折中。**

## 8. 决策记录（已定，不再重开）

- 零依赖、纯本地统计；共现只用 Map/对象，**禁止**向量库/余弦相似度/神经网络；
- **禁止**单次输入强建父子；只建可解释的平级相关边（阈值 + source_event_ids + GC）；
- 危险/破坏性操作必须显式确认（迁移、删除空间、安装插件均带 `confirm`）；
- 跨会话能力受 Host API 限制，采用"工作区文件 + Prompt"而非伪造事件；
- 市场发布必须 npm 已发布 + 目录条目，本地 `link` 包不会出现在市场。
